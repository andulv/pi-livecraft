# Workspace files

`FileExplorer.tsx` browses the selected workspace's files through the files API, lazily loading directory children. Its React Arborist tree virtualizes visible rows and handles keyboard navigation; the file filter applies to loaded children, while unloaded folders remain expandable. Single-click previews, double-click pins, and failed directory loads can be retried from the tree. After first opening Files, the explorer remains mounted (hidden on other workspace panels), preserving listings, expansion, selection, filter, and scroll until the workspace changes. Refresh rereads the root and every loaded folder, including collapsed ones; fresh parent listings prune deleted subtrees without reading them. Surviving expansion and selection remain; a deleted selection falls back to its nearest surviving parent or clears at the root. Failed refresh reads retain the previous subtree and show an error. The tree is temporarily inert during refresh to avoid racing expansion requests. `test/file-tree-data.test.ts` covers refresh pruning, failure retention, and selection fallback. `FileContentPane.tsx` previews explorer files and Git diffs beside the conversation: one tab strip, read-only content, and per-file loading/error states cached per workspace. A single-clicked file or diff uses the one replaceable italic preview tab; double-clicking its list entry or tab header pins it as an ordinary tab. Markdown files (`.md`, `.markdown`) render through the shared conversation `Markdown` component with frontmatter support; a header toggle switches between rendered and raw text views. Raster images and PDFs load as blobs from `GET /api/files/raw` — allow-listed media up to 25 MiB, owned by `server/workspace-file.ts` — through the viewers in `FilePreview.tsx`. HTML and SVG files keep their text fetch and add a `Preview`/`Source` toggle (HTML defaults to source); preview renders the text in a sandboxed iframe with an empty sandbox, no referrer, and a `default-src 'none'` content security policy, so previewed markup gets no scripts, network access, forms, or navigation. Markup previews zoom with header controls — a percent field offering a level dropdown, direct entry (committed on Enter or blur, clamped to 25%–400%), and 10% step buttons — that inject a `:root` zoom rule into the sandboxed document; the parent never scripts into the frame, and per-path zoom remembers each file's level. No key or mouse listeners drive preview zoom; the browser's own page zoom (Ctrl+wheel) still scales the whole app, and the PDF viewer keeps Chrome's native controls. Text reads refuse binary content, and failed previews offer the existing open-externally action. View modes are per path: switching tabs does not change another tab's rendered/raw state. Git diff tabs additionally toggle between the patch, original, and new file content; the original/new views use the same format-dispatch point, currently rendering Markdown and raw text. File content is never edited here. The pane also hosts the app's browser tab; see [browser](/src/features/browser/README.md).

`App.tsx` owns the pane share because it sizes the workspace grid's second column via `--file-pane-share`. The share is dragged on the pane's left separator (pointer or keyboard, mirroring the sidebar handles), persists in `pi-livecraft.file-pane-share`, and stays between 25% and 75% (`file-pane-width.ts`). The pane keeps a 280 px CSS minimum; above that minimum it grows and shrinks with the workspace, so sidebar changes preserve the chosen proportion. Below 900 px the pane and separator hide. Share bounds are covered by `test/file-pane-width.test.ts`.
