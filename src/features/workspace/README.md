# Workspace and sessions

`useProjects` owns the browser-local project registry and repository discovery. `ProjectHome` renders that registry at `/`; selecting a card writes the stable project ID to `?project=...`. `App.tsx` owns this small URL boundary so reload, duplicate-tab, back, and forward navigation preserve the selected project without introducing a frontend router. The same selection updates the browser title and favicon; `project-tab.ts` derives both from safe project metadata. Opening a registered project URL renders the project view immediately — `App` gates only on the local registry, not on discovery, so a slow registry scan never blocks entering a project. The project view validates its repository with its own `getGitProject` discovery and shows an unavailable screen (with retry) when that fails.

`useWorkspaceSessions` owns workspace selection and session lists for exactly one selected project. It coordinates refreshes, lazy creation, reopening, renaming and closing, optimistic naming, pending UI requests, and per-project workspace persistence. Selecting a workspace opens the newest listed session. An empty workspace shows a main-panel state surface that distinguishes loading, failed, and no-sessions; a session is created only through the New session action, which starts Pi immediately so model controls are available and keeps the empty session visible at the top of the session list. Repeating the action reselects that live empty session instead of creating another; navigating away stops and removes it unless a user message has succeeded. The project repository's main checkout and linked worktrees are the only selectable workspaces in that view. Persisted sessions can be pinned through their action menu; project-scoped pins move below the project heading, retain pin order across reloads, and open their owning workspace when selected. Pinned and workspace-local sessions share one secondary-colour row treatment; only the pin indicator distinguishes a pinned row, while workspace controls retain the project-accent bordered-card treatment. Workspace rows have an extensible `…` menu; its first action opens that exact worktree in VS Code. Turn-complete highlights are current-page notifications and reset on reload instead of reviving stale green rows.

Keep session-list reconciliation in this controller. The session list scans only the selected workspace (not every worktree), and pinned sessions load by their stored file paths via `/api/sessions/resolve` so pins never depend on a directory scan. The list refreshes on structural changes (session created/reassigned, rename, workspace switch) and on demand via the Sessions-header refresh button; it does not re-scan after each message, and a session exit only flips that session's live status. `App.tsx` supplies cross-feature callbacks, such as clearing feature state when the workspace changes or preparing an initial composer draft; it should not duplicate the controller's state.

Repository browsing and Git validation remain in `ProjectPicker`. Workspace paths accept both `~/...` and Windows `~\...`; completion preserves the separator style the user typed. Project identity, colour, and migration rules live in `projects.ts`; pure session-list rules live in `sidebar-sessions.ts`.
