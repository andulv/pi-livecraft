# Workspace and sessions

`useProjects` owns the browser-local project registry and repository discovery. `ProjectHome` renders that registry at `/`; selecting a card writes the stable project ID to `?project=...`. `App.tsx` owns this small URL boundary so reload, duplicate-tab, back, and forward navigation preserve the selected project without introducing a frontend router.

`useWorkspaceSessions` owns workspace selection and session lists for exactly one selected project. It coordinates refreshes, lazy creation, reopening, renaming and closing, optimistic naming, pending UI requests, and per-project workspace persistence. Selecting a workspace opens the newest listed session. An empty workspace selects an in-memory pending session and creates Pi only when its first message is sent. The new-session action starts Pi immediately so model controls are available and keeps the empty session visible at the top of the session list. Repeating the action reselects that live empty session instead of creating another; navigating away stops and removes it unless a user message has succeeded. The project repository's main checkout and linked worktrees are the only selectable workspaces in that view. Persisted sessions can be pinned through their action menu; project-scoped pins move below the project heading, retain pin order across reloads, and open their owning workspace when selected. Pinned and workspace-local sessions share one secondary-colour row treatment; only the pin indicator distinguishes a pinned row, while workspace controls retain the project-accent bordered-card treatment. Turn-complete highlights are current-page notifications and reset on reload instead of reviving stale green rows.

Keep session-list reconciliation in this controller. `App.tsx` supplies cross-feature callbacks, such as clearing feature state when the workspace changes or preparing an initial composer draft; it should not duplicate the controller's state.

Repository browsing and Git validation remain in `ProjectPicker`. Workspace paths accept both `~/...` and Windows `~\...`; completion preserves the separator style the user typed. Project identity, colour, and migration rules live in `projects.ts`; pure session-list rules live in `sidebar-sessions.ts`.
