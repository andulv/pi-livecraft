# Session environment backend capability

`EnvironmentService` coordinates manager commands, per-session refresh deduplication, restart restoration, and session availability. `EnvironmentCache` stores one report per Pi session and validates the versioned extension status payload — including optional extension source paths, estimated tool-definition character counts, and skill provenance — keeping the last valid value of each section when a newer report from the same session omits it. Reports never mix across sessions: an empty section from one project's session replaces only that session's own data. Session start publishes tools before a command context can read the system-prompt options, so context files arrive with a later refresh instead of blanking the tool list. `GET /api/environment` requires the `sessionId` query parameter.

HTTP paths and session identifier validation remain in `server/backend.ts`. Pi communication always uses `ManagerClient`. Main coverage: `test/session-environment.test.ts`.
