Move project · workspace · git context into the left sidebar

The top status bar currently mixes slow-changing workspace context (project, workspace, git) with fast-changing session data. Proposal: the sidebar — which has generous vertical space — becomes the home of workspace context; the top bar keeps only session state on two lines, and context usage joins the composer's existing bottom toolbar row — no added chrome. The main workspace gets its own card; the list below holds worktrees only. All colours below map to existing theme tokens, so both themes work unchanged.

Decisions & behaviour notes

What moved, what stayed, and why.

  1. Top bar = session only, two lines. Line 1: status dot + session name (the compacting state replaces this line while running). Line 2: usage stats, ellipsizing gracefully when the pane narrows. Context left the bar entirely.
  2. Context lives in the composer's existing bottom row. Right-aligned beside stop/send: Context 105k/272k + meter + %. No separate strip and no added height — the row and its divider already exist. On narrow panes it shrinks to the bare percentage (frame 3).
  3. Main workspace has its own card. Branch, path, and git summary — a stable section that never duplicates a list row. Highlighted only when main is the current workspace; clicking it selects main.
  4. The list is worktrees only. Each row: branch name, path sublabel (leading ellipsis keeps the tail visible). The selected worktree carries the git summary line — the snapshot already follows the selection, so at-a-glance git always sits next to “you are here”. With no worktrees the section hides entirely.
  5. Per-workspace session dots stay on the row's right edge; the … actions button appears on hover in the same slot (no layout shift).
  6. Collapsed keeps identity. The floating chip shows project ▸ branch plus a dirty dot; full path lives in the tooltip. Nothing else changes about collapse behaviour.
  7. No new data required. Everything shown already exists: gitSnapshot (already scoped to the selected workspace), projectDetails.workspaces, session.cwd. Colours reuse --accent/--success/--warning tokens, so light theme needs no separate palette.
